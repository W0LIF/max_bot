# Распределение задач между разработчиками — чат-бот на Go (MAX)

## Контекст проекта

**Трекер учебного баланса и профилактики выгорания для первокурсников** (из документа «Трек_ Образовательные решения.docx»).

Этот документ описывает распределение работ **только по чат-боту в MAX** (пакет `pkg/bot`, запуск `cmd/bot` — long-polling, деплой через `api/webhook.go` на Vercel). Мини-приложение (frontend) в этот объём **не входит**.

### Что должен уметь бот (объём работ)

1. Приветствие и онбординг нового пользователя.
2. Вопрос о согласии на обработку данных — кнопки **«Да» / «Нет»**.
3. Вопрос «Нужны ли напоминания о дедлайнах?» — кнопки **«Да» / «Нет»**.
4. Кнопки управления задачами: **«Добавить задачу» / «Удалить» / «Изменить»**.
5. Просмотр состояния (статуса) задач.
6. Отметка задачи выполненной (ответ «Выполнено» / кнопка).
7. Напоминания о дедлайнах (если пользователь согласился).

## Разработчик 1 — Backend и данные («ядро»)

**Зона ответственности:** хранение, бизнес-логика, всё, что не зависит от формата сообщений MAX.

| # | Задача | Что делаем | Где в коде |
| --- | --- |-----------| --- |
| 1 | Модель данных пользователя | Структура: ID пользователя MAX, флаг согласия (да/нет), флаг напоминаний, дата онбординга | новый `pkg/storage/` |
| 2 | Модель задачи | Структура: ID, ID пользователя, название, дедлайн, приоритет (по Эйзенхауэру: срочно/важно), статус (`новая` / `в работе` / `выполнена`) | `pkg/storage/` |
| 3 | Хранилище (SQLite) | Таблицы `users`, `tasks`; миграции при старте; выбор SQLite как простейшего варианта для старта (замена на Postgres позже) | `pkg/storage/sqlite.go` |
| 4 | CRUD задач | Функции: `CreateTask`, `GetTasks`, `UpdateTask`, `DeleteTask`, `SetTaskStatus` — с unit-тестами | `pkg/storage/` + `_test.go` |
| 5 | Логика статусов | Валидация переходов статусов (нельзя выполнить удалённую задачу и т.п.), сортировка списка задач по приоритету и дедлайну | `pkg/storage/` |
| 6 | API-слой для бота | Интерфейс `Store`, который использует Разработчик 2, чтобы не завязывать диалоги на SQL | `pkg/storage/store.go` |
| 7 | Шедулер напоминаний | Фоновый процесс (goroutine + ticker): раз в N минут ищет задачи с близким дедлайном у пользователей с включёнными напоминаниями и отдаёт их в очередь отправки | `pkg/reminders/` |
| 8 | Подключение хранилища к боту | Инициализация `Store` в `cmd/bot/main.go` и в `api/webhook.go`, проброс в `Dispatch` | `cmd/bot/`, `api/` |

**Результат Разработчика 1:** бот при запуске имеет рабочую БД, а диалоги Разработчика 2 вызывают готовые функции через интерфейс `Store`.

## Разработчик 2 — Диалоги и UX бота («лицо»)

**Зона ответственности:** всё, что пользователь видит: тексты, кнопки, сценарии диалога, ответы бота.

| # | Задача | Что делаем | Где в коде |
| --- | --- |-----------| --- |
| 1 | Приветствие и онбординг | По `/start` бот приветствует, затем спрашивает согласие на обработку данных с кнопками **«Да ✅ / Нет ❌»** | `pkg/bot/handlers.go` |
| 2 | Обработка согласия | Callback от кнопки «Да» → сохраняем согласие, переходим к вопросу о напоминаниях. «Нет» → вежливое сообщение, бот работает в ограниченном режиме (без хранения данных) | `pkg/bot/handlers.go` |
| 3 | Вопрос о напоминаниях | «Присылать напоминания о дедлайнах?» — кнопки **«Да / Нет»**, сохранение выбора | `pkg/bot/handlers.go` |
| 4 | Главное меню | Клавиатура с кнопками: **«➕ Добавить задачу» / «📋 Мои задачи» / «✏️ Изменить» / «🗑 Удалить» / «✅ Выполнено»** | `pkg/bot/menu.go` |
| 5 | Сценарий «Добавить задачу» | Бот спрашивает название → дедлайн → (опционально) приоритет, сохраняет через `Store.CreateTask`, подтверждает | `pkg/bot/dialog_add.go` |
| 6 | Сценарий «Мои задачи» (статус) | Вывод списка задач с их статусами и дедлайнами, отсортировано (данные даёт Разработчик 1) | `pkg/bot/dialog_list.go` |
| 7 | Сценарий «Изменить / Удалить» | Выбор задачи (inline-кнопки с номерами), затем новое значение или подтверждение удаления | `pkg/bot/dialog_edit.go` |
| 8 | Сценарий «Выполнено» | Пользователь выбирает задачу → статус меняется на `выполнена` → (заготовка под трекинг настроения 😊/😐/😴 из концепции) | `pkg/bot/dialog_done.go` |
| 9 | FSM диалогов | Простая машина состояний: «ожидаем название», «ожидаем дедлайн» и т.д., чтобы бот понимал, на какой вопрос отвечает пользователь | `pkg/bot/state.go` |
| 10 | Ответы на произвольные сообщения | Fallback: если пользователь пишет текст вне сценария — подсказка с главным меню | `pkg/bot/handlers.go` |

**Результат Разработчика 2:** пользователь проходит полный путь — согласие → напоминания → меню → добавление/просмотр/изменение/удаление/выполнение задач — только через переписку с ботом.

## Порядок работ (2 недели, примерный план)

### Неделя 1
- **Разр. 1:** модель данных, интерфейс `Store`, in-memory реализация, CRUD + тесты, начало SQLite.
- **Разр. 2:** онбординг (согласие да/нет, вопрос о напоминаниях), главное меню, FSM, сценарий «Добавить задачу».

### Неделя 2
- **Разр. 1:** SQLite-реализация, шедулер напоминаний, подключение к `cmd/bot` и `api/webhook.go`.
- **Разр. 2:** сценарии «Мои задачи», «Изменить», «Удалить», «Выполнено», fallback-ответы, тексты напоминаний.

### Контрольная точка (конец недели 2)
Полный сценарий через чат: `/start` → согласие → напоминания → добавление 2–3 задач → просмотр статуса → изменение → выполнение → получение напоминания.

## Точки сопряжения (важно!)

- Разработчик 2 **не пишет SQL** — только вызывает методы `Store`.
- Разработчик 1 **не пишет тексты кнопок** — только логику и данные.
- Формат callback-данных кнопок (например, `task:done:42`) согласовывается заранее и фиксируется в `pkg/bot/callback.go`.
- Статусы задач — общий enum в `pkg/storage/task.go`: `TaskNew`, `TaskInProgress`, `TaskDone`.
